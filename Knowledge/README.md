# Knowledge

Hand-maintained notes on *why* the system is built the way it is — decisions, tradeoffs, and conventions that aren't obvious from reading the source tree, so future sessions don't have to re-derive them by rereading the whole codebase.

This is distinct from `graphify-out/` at the repo root: that folder is an auto-generated knowledge graph (entities, code symbols, relationships) built by the `graphify` skill from a snapshot of the project. `Knowledge/` is smaller, curated by hand, and tracks decisions and rationale over time rather than structure.

- `architecture-decisions.md` — a running log of non-obvious design/architecture decisions and the reasoning behind them.

When you make a decision worth remembering (a convention adopted, a tradeoff made, a pattern deliberately avoided), add an entry here rather than letting it live only in a commit message or chat transcript.
